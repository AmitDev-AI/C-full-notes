C Preprocessor

Before compilation, the preprocessor scans the source for lines beginning with # and transforms the text. It knows nothing about C types or syntax — it only substitutes and includes.

#include

Copies the contents of another file into your source at that point.

#include <stdio.h>     // system header: search standard paths
#include <stdlib.h>
#include "myheader.h"   // local header: search the current directory first
FormSearchesUse for
<name.h>System include directoriesStandard and installed libraries
"name.h"Current directory, then system directoriesYour own project headers

#define: object-like macros

#include <stdio.h>

#define PI 3.141592653589793
#define MAX_USERS 100
#define PROGRAM_NAME "MyApp"

int main(void) {
    printf("%s supports %d users\n", PROGRAM_NAME, MAX_USERS);
    printf("PI = %.5f\n", PI);
    return 0;
}
Output
MyApp supports 100 users
PI = 3.14159

The preprocessor performs text substitution. PI is replaced everywhere before the compiler runs.

#define: function-like macros

#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define MIN(a, b) ((a) < (b) ? (a) : (b))

printf("%d\n", SQUARE(5));      // 25
printf("%d\n", SQUARE(2 + 3));  // 25
printf("%d\n", MAX(10, 20));    // 20
Output
25
25
20

Parenthesise everything. #define SQUARE(x) x * x makes SQUARE(2 + 3) expand to 2 + 3 * 2 + 3 = 11. Even with parentheses, arguments may be evaluated twice — prefer static inline functions for real logic.

#undef

#define TEMP 100
printf("%d\n", TEMP);   // 100

#undef TEMP
// printf("%d\n", TEMP);   // error: TEMP is no longer defined

Conditional compilation

Compile different code depending on macros. This is how one codebase supports several platforms.

#include <stdio.h>

#define DEBUG 1
#define VERSION 3

int main(void) {
#if DEBUG
    printf("Debug build\n");
#endif

#if VERSION >= 3
    printf("New API\n");
#elif VERSION == 2
    printf("Legacy API\n");
#else
    printf("Old API\n");
#endif

    return 0;
}
Output
Debug build
New API

#ifdef and #ifndef

#ifdef _WIN32
    #define PATH_SEPARATOR '\\'
#else
    #define PATH_SEPARATOR '/'
#endif

#ifndef BUFFER_SIZE
    #define BUFFER_SIZE 1024
#endif
DirectiveMeaning
#if exprCompile the block if expr is non-zero
#ifdef NAMECompile if NAME is defined
#ifndef NAMECompile if NAME is not defined
#elif exprElse-if for the preprocessor
#elseFallback branch
#endifEnds the conditional block

Include guards

If a header is included twice, its definitions appear twice and the compiler complains. Include guards prevent that.

#ifndef MYHEADER_H
#define MYHEADER_H

struct Point {
    int x;
    int y;
};

int distance_sq(struct Point a, struct Point b);

#endif  /* MYHEADER_H */

Many compilers also support the shorter #pragma once, but include guards are standard C.

Predefined macros

MacroMeaning
__FILE__Current source file name
__LINE__Current line number
__DATE__Compilation date
__TIME__Compilation time
__func__Current function name (C99, not a macro strictly)
__STDC_VERSION__Standard version, e.g. 201710L
 
#include <stdio.h>

#define LOG(msg) \
    printf("[%s:%d] %s\n", __FILE__, __LINE__, msg)

int main(void) {
    LOG("starting");
    LOG("finished");
    return 0;
}
Output
[main.c:6] starting
[main.c:7] finished

Stringizing and token pasting

#define STR(x) #x
#define XSTR(x) STR(x)
#define CONCAT(a, b) a##b

printf("%s\n", STR(hello));          // "hello"
printf("%s\n", XSTR(123));           // "123"
int CONCAT(my, var) = 5;             // int myvar = 5;

Preprocessor pitfalls

  • No type checking — macros accept anything.
  • Side effects — arguments can be evaluated more than once.
  • Operator precedence — missing parentheses change meaning.
  • Debugging — macro-expanded code is harder to step through.
  • Name clashes — macros ignore scope and can replace unintended identifiers.
  • Semicolons — never end a macro definition with ; unless you want it in every expansion.

Viewing preprocessor output

gcc -E main.c -o main.i      # stop after preprocessing
gcc -E -dM main.c            # list all macros

Reading the preprocessed output is the fastest way to understand why a macro is misbehaving.

Tip: use the preprocessor for inclusion, platform switches and simple constants; use const, enum and static inline functions for everything the type system can check.

Exercises

  1. Write a header file with an include guard and include it twice in one file.
  2. Create a SQUARE macro and verify it works with expressions.
  3. Use #ifdef to print different messages on Windows and Linux.
  4. Write a LOG macro that prints the file, line and message.
  5. Run gcc -E on a small file and inspect the expansion.
